# Import participant detection — 25 September 2026

User-requested flow: paste/open text, click **Detect participants**, then select yourself. Detection sends only the first20 physical lines (maximum8000 characters) to the shared Luna model at low effort, currently gpt-5.6-luna. The remaining transcript is parsed locally without model rewriting. The other speaker is explicitly shown as linked to the contact selected on Home. Nothing is saved before **Import and generate**.

The original selector stayed empty when the narrow WhatsApp parser produced no turns. The new flow supports explicit `Name: message` transcripts (optional leading clock time) and the existing month/day WhatsApp export formats. Standalone names are not speaker changes. Exactly two speakers must be visible in the sample; unknown explicit speaker headers later in the full text are rejected. Undated text remains undated instead of acquiring invented timestamps. Imported records enter the existing automatic summary/memory review pipeline.

Safeguards: bounded structured output; names verified against actual headers; no model-generated code/regex; transcript treated as untrusted evidence; detection runs on a worker; duplicate clicks disabled while pending; editing clears the confirmed preview; closing invalidates late results; API failures leave editable text and an explicit retry action. In-session import usage shares an app-owned ledger across dialog closures and failures; it is separate from historical evaluation ledgers. No new global durable product-accounting system was added. Existing generation receipts continue to describe only summary/extraction requests.

Format limits: both people must appear within the first20 lines. Unlabelled prose and name-only headings need explicit `Name:` labels. Plain-format continuation lines that look like unknown `Name:` headers are rejected conservatively; a quoted known-name header is inherently ambiguous and should be kept within its message line. In dated WhatsApp exports, only dated headers switch speakers; colon/URL continuations are retained and senderless system notices are excluded. Plain-first text switching to dated headers is rejected. WhatsApp month/day and assumed local timezone behavior remains disclosed; arbitrary locale/date formats are not added.
